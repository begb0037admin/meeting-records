# Speaking-brief template

Generates the HTML that gets published as a Claude Artifact for Kevin to read from live in a meeting: Oxford brandbar, live clock + meeting stopwatch, dual-month calendar (today highlighted), a flagged data-gap warning, an "at a glance" summary table, and a grid of per-item cards with a "say this" line for each.

## Standing monthly process: KPI Presentation

This section is a self-contained runbook for the monthly KPI Presentation deck — readable without any prior context on how Kevin's agents are organised.

**What it is.** `build_kpi_presentation.py` is not one of the `brief_chrome.py`-based HTML/Artifact briefs — it edits a real `.pptx` file directly (via `python-pptx`, `openpyxl`, `python-docx`, `matplotlib`) to produce the monthly **KPI Presentation** deck, the actual KPI figures/statistics deck sent for the monthly team meeting. It is the higher-priority of two separate monthly decks — do not confuse it with the Monthly Standing Agenda deck, which lives under `KPI Monthly Standing Agenda/` and uses a completely different, template-based pipeline with its own style rules.

**Cadence: one month in arrears.** A given month's deck (e.g. July 2026's) is built during the *following* month (e.g. early August 2026), once that month's Source Data export is finalised and available. The build copies forward the most recent finished real deck (e.g. June 2026's) as its base file, then writes the new month's figures into that copy — it does not build a blank deck from scratch each time.

**Source data — local OneDrive, never this repo.** Each month has its own folder: `Functional Analysis Team Monthly Statistics\{YYYY}\{MM Mon}\Source Data\`, containing an Excel workbook and an H&S Word document. This is a local OneDrive path, not anything committed to `meeting-records` — the script needs direct filesystem access to it and is not runnable from a sandbox without that access.

**Mandatory gate before trusting any new month's output.** The script carries its own bundled self-test: running `python build_kpi_presentation.py` with no arguments rebuilds June 2026 end-to-end from June's own Source Data and diffs every table cell across all 11 slides against the real, known-correct June 2026 deck, plus independent chart-value checks. This must pass clean before the script is trusted against a new month. One disclosed, understood 0.01-percentage-point rounding gap remains on slide 7's "LESS THAN 5 DAYS" combined metric (documented in the script's own comments) — not a blocker, just a known and accepted limitation, not something a future session should try to "fix" without first re-reading why it's there.

**7 August 2026 — pipeline extended and independently re-verified.** Drew (`begb0037admin/drew`, who engineers this pipeline) extended the script to close a gap where several slides looked complete in test output but were actually still silent pass-through from the base deck: native `chart.replace_data()` writes for the pie charts on slides 2/3/4/6/7, table writes for slides 2/3/6/7/10, automatic H&S prior-month carry-forward, and a real ordering-bug fix on slide 5's Table 6 (the blank-row removal must run before the Total-row write, not after). Lauren then independently reran the extended pipeline from a fresh pull of the script against **July 2026's own Source Data**, deliberately not opening Drew's already-built July deck until her own run and hand-verification against the raw source were complete, then diffed the two outputs: **zero divergence** across all 11 slides, all native chart series, and byte-identical (SHA1) regenerated chart images. Full account of what was run and how: `begb0037admin/lauren`, `memory/kpi-presentation-independent-verification-july.md` (the verification run itself) and `memory/kpi-presentation-assembly-gap.md` (the gap this closed). This independent re-run is what makes the pipeline trustworthy as a genuine standing monthly process, not just a one-off demo that happened to look right.

**Ownership.** Drew engineers `build_kpi_presentation.py` itself — fixes, extensions, new capabilities. Lauren owns running it monthly, curating/reviewing the output, and cross-referencing `work-inbox`/`command-centre` before anything is treated as final (see "Data sources beyond this repo" below). This is the general "engineer once, hand off as a standing task" split documented cross-agent in `begb0037admin/agent-commons`.

## Design notes — Unresolved conflicts sections

Where a brief's Unresolved conflicts section has more than one genuinely separate point, it's built as multiple `.risk-block` divs (bold `.risk-head` title + body copy each, divider between blocks) rather than one running paragraph — restructured 2 Aug 2026 on `build_roadmap.py`, `build_managers_meeting.py`, and `build_sk_1on1.py` after the flat-paragraph version read as a single wall of text. `build_hs_roadmap.py` was left as a single point deliberately (see above) — the `.risk-block` CSS in `brief_chrome.py` still applies cleanly to a lone block, it just doesn't get a divider (`:last-child` has none).

## Running a build script

Each `brief_chrome.py`-based script is self-contained except for two binary inputs it expects to find alongside it (not committed here — they're large/generated, not source): `inter-400/600/700/800.woff2` (Inter, subset + WOFF2-converted via `fontTools.subset`) and `oxford-crest.jpg` (the canonical crest referenced in `command-centre/BRANDING.md`). Point `SCRATCH` in `brief_chrome.py` at a working directory containing those, then `python build_roadmap.py` (etc.) writes the finished HTML there, ready to hand to the `Artifact` tool.

`build_kpi_presentation.py` is different — it needs `python-pptx`, `openpyxl`, `python-docx`, `matplotlib`, and `numpy` installed, and direct filesystem access to the local OneDrive source folder above (it is not runnable from a sandbox without that access). Run it directly (`python build_kpi_presentation.py`) to self-test, or import `build_month(year, month)` to build a specific month's deck — see the file's own docstrings for the full contract (`build_month`, `populate_deck`).

Every generated brief is a draft only — nothing here writes to `meeting-records`, publishes, or schedules anything on its own. `build_kpi_presentation.py` writes directly to the local OneDrive KPI Presentation archive (not this repo) when given real month/year arguments — treat that as a real, consequential write, not a draft.
